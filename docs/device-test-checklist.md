この文書はローカルテストZIP内では`DEVICE-TEST-CHECKLIST.md`として使います。作者は`upiscium`、独自コードは`AGPL-3.0-or-later`、クライアント内部版は`0.1.1`、GitHubリリースのタグ名は`v0.1.1`です。Bridgeは0.1.0のままです。**この試験票は、公開リリースの合格判定やWindows／Androidのサポート宣言ではありません。** 配布はGitHubのみを対象とし、公式Community Pluginsへの申請は行いません。公開状況は`upiscium/ObsidianCore-Sync`のReleasesを確認してください。既存workspace pathと内部ID・状態は維持します。LICENSE／NOTICE／第三者通知と対応ソースZIPを保持し、手順と停止条件は`START-HERE.md`を先に読んでください。

クライアント旧表示名`VaultSync`から新表示名`ObsidianCore Sync`への対応は表示上の変更準備です。安定した技術識別子は改名しません。コマンドパレットの表示ラベルは`ObsidianCore Sync: ...`ですが、コマンドIDは`vaultsync:...`のままです。

| 項目 | 安定した識別子／扱い |

| プラグインID／インストール先 | `vaultsync`／`.obsidian/plugins/vaultsync/`を維持 |

この更新には状態ファイルの移行はありません。プラグインフォルダーを改名したり、設定や状態を削除したりしないでください。Bridgeの配布ファイルは0.1.0のまま変更せず、サーバー側の再導入・構成変更は不要です。

この更新時点で、Windows／Androidを含む以下の実機チェック項目はすべて `未実施` です。自動テストの結果や過去のLinux／fixture観察を、実機での成功として転記しないでください。

## 基本同期・変更・競合

各行は合成データで実施します。状態欄には `未実施`、`成功`、`失敗`、`該当なし` のいずれかを手書きし、失敗時はすぐ同期を止めます。

競合試験の前には、同じ合成ノートを一度両端末で同期して共通の基準版を作り、自動同期OFFのまま両側を編集してから順に手動同期します。共通基準のない初回の内容違いは、自動マージではなく初回競合になるのが正常です。

## テスト報告用の最小テンプレート

秘密情報や実データを含めず、実際に確認できた項目だけを記入します。必要な場合だけ確認済みの限定診断JSONを任意で添付できます。画面写真、設定ファイル、全HTTPトレース、エラー原文は添付しません。

```text
端末種別: [ ] Windows  [ ] Android
端末ラベル: [ ] A  [ ] B（個人名・端末名は書かない）
実インストール ObsidianCore Sync アプリ版（手書き）:
ZIPのSHA-256（任意）:
Obsidian版（手書き）:
診断のObsidian API版（別情報）:
Nextcloud版（手書き）:
Bridge API／プロトコル版（アプリ版とは別）:
確認したチェック番号:
状態: 未実施 / 成功 / 失敗 / 該当なし
テスト条件: 合成データのみ／一般的な説明
観察: ファイル名・URL・アカウント・Vaultパス・本文を含めない
```

未実施の行はそのまま `未実施` とし、他端末の結果を転記しません。ここでの成功は当該端末・当該テスト条件だけの観察であり、新しい対応・サポート・公開リリースの主張ではありません。
